# saves · 存档系统

## Purpose

定义自动、手动存档槽、跨版本迁移链、导入导出与损坏兜底。存档是玩家的信任资产，以下所有兜底设计都为"永不丢进度、老档永远能读"服务。

## Requirements

### Requirement: 槽位与自动存档
存档 UI SHALL 提供 1 个自动槽 + 3 个手动槽（保存/读取/时间戳）。游戏 MUST 周期性静默自动存档到自动槽，不打断操作、不弹窗。

#### Scenario: 自动存档静默写入
- **WHEN** 游戏中经过一个自动存档周期
- **THEN** 自动槽内容更新且无任何模态打断

#### Scenario: 手动槽往返
- **WHEN** 保存到手动槽 1 → 改变世界 → 读取槽 1
- **THEN** 金币/建筑/队员状态回到保存时点

### Requirement: 版本迁移链
当前存档版本为 v5。读取任何历史版本 MUST 沿迁移链逐级升到当前版本（v1→v5 补技能、属性、性格/情绪等字段），字段一旦升级不降级；新版本读旧档不报错、旧字段语义不丢失。

#### Scenario: v1 直升 v5
- **WHEN** 载入 v1 存档
- **THEN** 迁移链完整执行到 v5，技能/属性/性格字段以默认值补齐，单位数据保留

#### Scenario: 已是当前版本不重迁移
- **WHEN** 载入 v5 存档
- **THEN** 数值与性格字段原样恢复，不被重新生成

### Requirement: 导入导出
玩家 SHALL 能把槽位存档导出为 JSON 文件、并从外部 JSON 导入；导入成功 MUST 触发按该存档的世界重建（刷新后按导入档初始化）。

#### Scenario: 导入外部档
- **WHEN** 导入构造的合法 JSON 存档并刷新
- **THEN** 世界按导入内容初始化（金币/人员/物资一致）

### Requirement: 损坏存档兜底
存档解析失败时 MUST NOT 白屏卡死：SHALL 回退为开新档并在日志提示读档不可用。

#### Scenario: 破损 JSON
- **WHEN** 本地存档被写入非法 JSON 后加载游戏
- **THEN** 游戏正常进入新档，日志出现存档不可用提示

### Requirement: 读档恢复范围
读档 SHALL 恢复：角色（含背包/属性/状态）、金币、建筑、农田、船进度与时辰；树/岩石/浆果与野狼 MUST 重新生成（世界是活的，只存关键进度）。

#### Scenario: 建筑与农田恢复
- **WHEN** 建好木屋农田后存档并读档
- **THEN** 木屋与农田状态原样出现，树木重新可采集
