# v0.4 · 背包交互打磨（S5）规格

> 版本：v0.4 · 状态：已实现并回归（2026-10-22）
> 目标：让背包管理从"一次 1 个、干巴巴"升级为"批量操作 + 有味道的悬浮详情"——呼应六关键词里的「荒诞」文案载体。

## 1. 目标

- **批量转移/丢弃**：转移浮层加数量控件（− / ＋ / 全部），一次转 N 个；目标行显示该队员可接收数量。
- **物品悬浮详情**：背包每行 hover 展开物品描述（重量 + 荒诞文案），文案来自 `ITEMS.desc`（单一数值源）。
- 拖拽交互本轮不做（复杂度高、窄屏验证受限），留档「后续」。

## 2. 数据与文案（`src/config.ts`）

`ITEMS` 每个物品增加 `desc`（荒诞描述）：

| 物品 | 重量 | desc |
| --- | --- | --- |
| 木材 | 2 | 荒野唯一的硬通货——树倒了，价没倒。 |
| 石头 | 2 | 商人说这石头会唱歌，但没人真听到过。 |
| 食物 | 1 | 吃下去能撑一阵。别问是什么做的。 |
| 种子 | 1 | 种下去是希望；种歪了，就长成浆果。 |
| 浆果 | 1 | 吃了可能看见幻觉——狼在跳舞那种。 |

## 3. 交互实现（`src/ui/hud.ts` + `index.html` 样式）

- 转移浮层重构为 `renderTransferPicker()`：
  - 标题：`木材 · 背包 30 个`
  - 数量行：`− [n] ＋ 全部`（`data-act=qty-down/up/all`；n 默认 1，上限=持有数）
  - 目标行：`给 克莉 ×n（可收 13 · 负重 35%）`——可收 = `floor((目标容量-负重)/重量)`，与 `invCanAdd` 口径一致
  - 丢弃：`丢弃 ×n`；取消不变
- 事件委托在 `#invPicker` 容器（浮层每次重建 DOM，委托避免重绑；连续点击安全）。
- 批量转移复用 `transferItem(from, to, id, n)`（v0.3 已支持 n，无需改逻辑层）。
- 悬浮详情：背包行内嵌 `.invDesc`（`重 w/个 · desc`），CSS `.invRow:hover .invDesc{display:block}` 展开。

## 4. 验证

- 回归：`scripts/regress.sh` 七步（tsc → build → 产物 → 迁移 15 → 技能 24 → 价格 17 → 修船 9）保持全绿；S5 为 UI 交互，无新增 node 自检（DOM 无 node 环境）。
- 实机（`?debug=1`，注入 v3 存档：罗恩 wood30 于原点）：
  - 选中罗恩（点选）→ 背包面板显示木材×30/石头×10…
  - 悬浮详情 DOM：`#invList .invDesc` 五行，首行 `重 2/个 · 荒野唯一的硬通货——树倒了，价没倒。`
  - 开木材浮层：`木材 · 背包 30 个` + `− [1] ＋ 全部`
  - ＋ ×4 → n=5；目标行 `给 拓荒者·克莉 ×5（可收 13 · 负重 35%）`（克莉容量 40-14=26/2=13 ✓）
  - 给克莉 ×5 → 罗恩 wood 30→25（负重 86→76）、克莉 wood 3→8（负重 14→24）
  - 再开浮层 → 全部 → n=25 → 丢弃 ×25 → 罗恩 wood 25→0（负重 76→26）、日志「丢弃了 木材 ×25」
- 环境限制：窄屏（235×848）无坐标 hover API，悬浮详情视觉展开为间接验证（DOM 内容 + CSS 规则已确认；桌面宽屏 hover 正常）。
